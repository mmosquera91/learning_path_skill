## FIX-03: Add Explicit Error Handling to daily.md

**Three failure points requiring try/except:**

### 1. LLM Task Generation (Step 6)
Wrap the LLM call in try/except. If it fails or returns invalid JSON:
- Retry once with: "Output valid JSON only, no markdown, no explanation"
- If retry fails: send user a message "No pude generar la tarea. Intenta de nuevo mas tarde." and END
- Do NOT write to DB or send Telegram if task generation fails

### 2. Database Write (Step 7)
Wrap the INSERT and UPDATE in try/except:
- If `sqlite3.OperationalError` or other DB error: report error to user
- Do NOT send Telegram message if DB write fails (no task to send)
- Do NOT leave partial state

### 3. Telegram Delivery (Step 8)
Wrap the Hermes deliver call in try/except:
- If deliver fails: report error to user "No pude enviar la tarea. Intentare de nuevo manana."
- Do NOT mark task as sent if delivery fails

**Pattern to follow (from eval.md and init.md):**
```markdown

    # specific failure point 1

    # rollback if needed, report error, do NOT leave partial state
```

- Do NOT use bare `except:` — use specific exception types
- Do NOT silently continue after failure — report to user
- "Silent exit" is only appropriate for "no active path" case (already correct)
- Error messages to user should be in Spanish (matching persona)
