## Directory Purposes

**Root directory (`~/.hermes/skills/tutor/`):**
- Purpose: Hermes Agent skill root. Contains the main router, documentation, and skill metadata.
- Contains: Markdown files (SKILL.md, README.md, AGENTS.md, CONTRIBUTING.md), LICENSE, .gitignore
- Key files: `SKILL.md` (the router — everything starts here), `AGENTS.md` (developer reference)

**`subskills/`:**
- Purpose: Domain logic modules loaded on demand by the router or inlined into cron prompts
- Contains: Four Markdown files, each representing a complete workflow (init, daily, eval, adapt)
- Key files:
  - `subskills/init.md` — Longest and most complex (258 lines). Handles web research, syllabus generation, URL validation, DB save, and cron job creation.
  - `subskills/eval.md` — Most critical for correctness. Contains evaluation pipeline and score-driven state transitions.
  - `subskills/daily.md` — Most frequently executed (runs daily at 9 AM). Contains inactivity escalation logic and spaced repetition checks.
  - `subskills/adapt.md` — Weekly review with performance metrics and adaptation rules.

**`templates/`:**
- Purpose: Pure formatting templates for user-facing output. No logic, no SQL, no decision trees.
- Contains: Five Markdown files using Mustache-style placeholders (`{{variable}}`, `{{#section}}...{{/section}}`)
- Key files:
  - `templates/evaluation.md` — The evaluation rubric with scoring criteria and the strict JSON output schema the LLM must follow
  - `templates/syllabus.md` — Mustache template for presenting syllabi with verified/unverified resource indicators

**`scripts/`:**
- Purpose: Python utilities called by subskills for database and URL operations
- Contains: Three Python scripts (init_db.py, migrate_db.py, validate_urls.py)
- Key files:
  - `scripts/init_db.py` — Defines the complete SQLite schema (6 tables). Idempotent (CREATE IF NOT EXISTS).
  - `scripts/migrate_db.py` — Version-based migration engine. Compares DB schema_version against EXPECTED_VERSION and runs ALTER TABLE deltas.
  - `scripts/validate_urls.py` — Standalone CLI tool (217 lines). Classifies URLs by tier using regex patterns, checks HTTP status via curl. Supports single URL check (`--check`), file input (`--file`), and stdin pipe.

**`.planning/codebase/`:**
- Purpose: GSD planning documents generated by codebase analysis
- Contains: ARCHITECTURE.md, STRUCTURE.md (and other analysis docs from other focus areas)
- Generated: Yes
- Committed: Yes

## Key File Locations

**Entry Points:**
- `SKILL.md`: Primary entry point — Hermes loads this when the skill is invoked. Contains the command router table and persona.
- `subskills/daily.md`: Cron entry point for daily tasks (9 AM). Inlined verbatim into the cron prompt.
- `subskills/adapt.md`: Cron entry point for weekly review (Sunday 10 PM). Inlined verbatim into the cron prompt.
- `scripts/init_db.py`: Script entry point for DB initialization. Called at start of every cron and `/tutor init`.

**Configuration:**
- `.gitignore`: Defines what is excluded from version control (learning.db, WAL files, editor files)
- `SKILL.md` lines 1-6: Frontmatter with skill name, version, author, and argument hint
- `scripts/migrate_db.py` line 17: `EXPECTED_VERSION` — the target schema version for migrations
- `scripts/validate_urls.py` lines 16-48: `TIER_PATTERNS` — regex patterns for URL classification by tier

**Core Logic:**
- `subskills/init.md`: Syllabus generation workflow (web research, LLM generation, URL validation, DB save, cron creation)
- `subskills/eval.md`: Evaluation pipeline (task retrieval, LLM scoring, JSON parsing, state transitions)
- `subskills/daily.md`: Daily task delivery (path check, inactivity handling, task generation, Telegram delivery)
- `subskills/adapt.md`: Weekly adaptation (metrics aggregation, adaptation rules, report generation)
- `templates/evaluation.md`: Scoring rubric and JSON output schema that constrains LLM evaluation output

**Documentation:**
- `AGENTS.md`: Developer reference — architecture decisions, state model, extension guide, testing checklist, roadmap
- `README.md`: User documentation — commands, setup, cron behavior, evaluation rubric, known limitations
- `CONTRIBUTING.md`: Contributor guide — URL validation system, testing instructions, PR process

**Testing:**
- `CONTRIBUTING.md` line 63: Test command for URL validation (`python3 -m pytest scripts/test_validate_urls.py -v`)
- `AGENTS.md` lines 315-365: Manual testing checklist covering init, daily, evaluation, weekly review, state management, and spaced repetition flows
- Note: No automated test files exist in the current codebase. Testing is primarily manual via the checklist in AGENTS.md.

## Naming Conventions

**Files:**
- Skill metadata: `SKILL.md` (uppercase, standard Hermes convention)
- Subskills: lowercase with `.md` extension — `init.md`, `daily.md`, `eval.md`, `adapt.md`
- Templates: lowercase with hyphens and `.md` extension — `daily-task.md`, `weekly-report.md`
- Scripts: lowercase with underscores and `.py` extension — `init_db.py`, `migrate_db.py`, `validate_urls.py`
- Documentation: uppercase with `.md` extension — `README.md`, `AGENTS.md`, `CONTRIBUTING.md`

**Directories:**
- `subskills/`: one word, lowercase
- `templates/`: one word, lowercase
- `scripts/`: one word, lowercase
- `.planning/codebase/`: lowercase, nested planning structure

**Database Tables:**
- `config`, `paths`, `modules`, `daily_tasks`, `resources`, `schema_version` — all lowercase with underscores for multi-word names
- Foreign keys: `path_id`, `module_id` — singular table name + `_id`

**Database Columns:**
- snake_case throughout: `is_active`, `awaiting_response`, `response_window_end`, `module_order`, `score_avg`, `times_repeated`
- Status values: lowercase strings — `pending`, `in_progress`, `completed`, `draft`, `active`, `paused`
- Boolean columns: INTEGER (0/1) — `is_active`, `confirmed`, `awaiting_response`, `skipped`

**Config Keys:**
- snake_case with underscores — `active_path_id`, `pending_task_id`, `last_response_date`, `streak_count`, `daily_count`, `weekly_count`

**Cron Job Names:**
- Lowercase with hyphen: `tutor-daily`, `tutor-weekly`

## Where to Add New Code

**New Command (e.g., `/tutor <newcommand>`):**
1. Add the command row to the ROUTER table in `SKILL.md` (section "ROUTER — Command Dispatch")
2. Either:
   - Add inline SQL and logic directly in `SKILL.md` (for simple state queries like `/tutor status` or `/tutor skip`)
   - Create a new subskill file at `subskills/<commandname>.md` (for complex flows > 30 lines)
3. Update the command table in `README.md`
4. If the command modifies the DB schema, update both `scripts/init_db.py` and `scripts/migrate_db.py`

**New Subskill (new workflow with its own trigger):**
- Implementation: `subskills/<name>.md`
- Follow the pattern: trigger section at top, numbered steps with inline SQL, LLM prompts, error handling
- Reference templates from `templates/` for any output formatting
- If this subskill runs as a cron job, it will be inlined verbatim into the cron prompt — ensure it is fully self-contained

**New Template (output format):**
- Implementation: `templates/<name>.md`
- Use Mustache-style placeholders: `{{variable}}`, `{{#section}}...{{/section}}`, `{{^section}}...{{/section}}`
- No logic, no SQL — formatting only
- Reference the template in the subskill that uses it

**New DB Column or Table:**
1. DO NOT modify `scripts/init_db.py` schema for existing installs — only for fresh installs
2. Edit `scripts/migrate_db.py`: increment `EXPECTED_VERSION`, add ALTER TABLE migration entry
3. Update `scripts/init_db.py` CREATE TABLE to include the new column for fresh installs
4. Run `python3 scripts/migrate_db.py` to apply
5. Update all subskills that query the affected table

**New URL Validation Pattern:**
- Edit `scripts/validate_urls.py`, add regex entry to `TIER_PATTERNS` dict at the appropriate tier level
- Test with `python3 scripts/validate_urls.py --check "https://new-pattern-url.com/..."`
