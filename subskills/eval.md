# Subskill: Evaluation — Score and Feedback

## Trigger
- User sends `/submit <response>`
- OR user sends a message while pending_task_id is active AND within the 20h response window
  (in this case, ask for confirmation first: "Is this your submission for today's task? Reply yes or /submit <response>")

## Steps

### 1. Get pending task
```sql
SELECT t.id, t.content, t.date, t.response_window_end, m.title, m.id as module_id, m.path_id
FROM daily_tasks t
JOIN modules m ON t.module_id = m.id
WHERE t.awaiting_response = 1
  AND t.skipped = 0
ORDER BY t.date DESC LIMIT 1;
```
If no pending task → tell user "No pending task to evaluate. Use /tutor status."

### 2. Check response window
If current time > response_window_end AND this isn't an explicit /submit:
→ treat as normal conversation, not a submission.

### 3. Evaluate the response
Load templates/evaluation.md for the rubric.

Use the LLM with this evaluation prompt:
```
You are evaluating a student's response to a learning task.

MODULE: {module_title}
TASK GIVEN: {task_content}
STUDENT RESPONSE: {user_response}

Evaluate using the rubric from the evaluation template.
Be specific in feedback — cite exact parts of their response.
Return ONLY valid JSON matching the evaluation schema:
{
  "conceptual_comprehension": <1-10>,
  "application_ability": <1-10>,
  "score": <average, 1 decimal>,
  "decision": "<advance|repeat|decompose>",
  "feedback": "<specific feedback>",
  "strengths": ["<...>"],
  "improvements": ["<...>"],
  "next_review_days": <1|3|7>
}
```

### 4. Parse evaluation result
Extract the JSON from the LLM response. If invalid JSON, retry once.

### 5. Apply decision rules

**score >= 7.0 → ADVANCE:**
```sql
UPDATE modules SET
  status = 'completed',
  score = {score},
  score_avg = COALESCE((score_avg * times_repeated + {score}) / (times_repeated + 1), {score}),
  times_repeated = times_repeated + 1,
  completed = '{now}',
  next_review_date = date('{now}', '+{next_review_days} days')
WHERE id = {module_id};

-- Mark module for spaced repetition review
-- (status='completed' but next_review_date set means it will be picked up for review)
```

Send milestone celebration using templates/milestone.md if this was a completion.

**score 4.0-6.9 → REPEAT:**
```sql
UPDATE modules SET
  score = {score},
  score_avg = COALESCE((score_avg * times_repeated + {score}) / (times_repeated + 1), {score}),
  times_repeated = times_repeated + 1,
  next_review_date = date('{now}', '+{next_review_days} days')
WHERE id = {module_id};
-- Module stays in_progress, will get a new task next session
```

**score < 4.0 → DECOMPOSE:**
```sql
-- Insert sub-modules after the current module
-- Shift module_order for all subsequent modules
UPDATE modules SET module_order = module_order + 2 WHERE path_id = {path_id} AND module_order > {current_order};

-- Insert 2-3 sub-modules (generated by LLM based on the module)
INSERT INTO modules (path_id, title, description, module_order, status) VALUES
  ({path_id}, '{sub1_title}', '{sub1_desc}', {current_order}, 'pending'),
  ({path_id}, '{sub2_title}', '{sub2_desc}', {current_order}+1, 'pending');

-- Reset current module to pending (to be revisited after sub-modules)
UPDATE modules SET status = 'pending', score = NULL WHERE id = {module_id};
```

### 6. Save evaluation to task
```sql
UPDATE daily_tasks SET
  response = '{user_response_escaped}',
  feedback = '{feedback_escaped}',
  score = {score},
  awaiting_response = 0
WHERE id = {task_id};
```

### 7. Update config
```sql
UPDATE config SET value = '{now}' WHERE key = 'last_response_date';
UPDATE config SET value = '' WHERE key = 'pending_task_id';
```

### 8. Send feedback to user
Format:
```
📋 Evaluation — {module_title}
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Score: {score}/10

{feedback}

✅ Strengths: {strengths}
📈 Improve: {improvements}

{decision_message}
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

Where decision_message:
- advance: "Great work! Moving to next module: {next_module_title}"
- repeat: "Let's reinforce this. I'll prepare a new task for next session."
- decompose: "This topic needs more groundwork. I've broken it into smaller steps: {sub_modules}"

### 9. Check adaptation triggers (Fase 3)
After saving evaluation, check:
- 2 consecutive scores 4-6.9 → add a supporting resource
  ```sql
  INSERT INTO resources (module_id, url, title, type, verified) VALUES
    ({module_id}, '', 'Additional practice (auto-generated)', 'exercise', 'unverified');
  ```
  + Notify: "I've flagged this module for extra support. Next task will include additional practice."

- 3 consecutive modules with score >= 9 → offer acceleration
  Send: "🚀 You've been crushing it (3 modules at 9+). Want to skip ahead? /tutor accelerate to jump to advanced content."
